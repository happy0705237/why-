## 2. 风险清单

### R01 — 大目录扫描性能

| 维度 | 详情 |
|------|------|
| **风险描述** | 扫描包含百万级文件的目录（如整个 C 盘）时，扫描时间过长或内存溢出 |
| **影响** | 高 — 直接影响核心功能可用性 |
| **概率** | 高 — 用户很可能选择扫描整个用户目录或磁盘 |
| **影响范围** | 扫描功能、用户体验 |
| **缓解措施** | 1. 使用 `os.scandir()` 替代 `os.listdir()`，底层调 Windows FindFirstFile API<br>2. 采用流式处理：扫描一批写入一批，不全部加载到内存<br>3. 使用 `ThreadPoolExecutor` 并发扫描子目录（默认 4 线程）<br>4. 设置 `max_depth` 限制，默认 20 层<br>5. 设置扫描超时（默认 300 秒）<br>6. 前端显示扫描进度，让用户感知到进度 |
| **应急预案** | 如果性能仍不达标，引入快速扫描模式：只统计目录层级大小，不记录每个文件 |
| **验收标准** | 10 万文件 < 10 秒，100 万文件 < 60 秒，内存 < 500MB |

### R02 — 文件权限与锁定

| 维度 | 详情 |
|------|------|
| **风险描述** | 部分系统目录、被占用的文件无法访问或删除 |
| **影响** | 中 — 影响扫描完整性和清理执行 |
| **概率** | 高 — Windows 系统目录几乎必然遇到 |
| **影响范围** | 扫描结果准确性、清理操作成功率 |
| **缓解措施** | 1. `try-except` 包裹每个文件操作，权限不足时记录错误但不中断<br>2. 默认排除系统关键目录：`C:\$Recycle.Bin`、`C:\System Volume Information`、`C:\Windows`<br>3. 扫描完成后汇总错误数，前端提示"跳过了 N 个无权限文件"<br>4. 删除操作捕获 `PermissionError`，提示用户"文件正在被使用" |
| **验收标准** | 扫描不因权限问题中断，错误被优雅处理并记录 |

### R03 — SQLite 大数据量

| 维度 | 详情 |
|------|------|
| **风险描述** | 100 万文件的扫描结果写入 SQLite 时，写入速度慢或数据库文件过大 |
| **影响** | 中 — 影响扫描速度和存储空间 |
| **概率** | 中 — 只有扫描超大目录时才触发 |
| **影响范围** | 扫描性能、磁盘占用 |
| **缓解措施** | 1. 批量插入：使用 `executemany` + 事务，每 5000 条提交一次<br>2. 索引优化：只在必要字段建索引，扫描完成后再建辅助索引<br>3. 数据库路径放在用户目录下（`~/.diskmanager/`），不占项目空间<br>4. 历史数据自动清理：默认保留最近 10 次扫描或 90 天<br>5. 定期 VACUUM 回收空间 |
| **验收标准** | 10 万文件写入 < 5 秒，数据库文件 < 100MB |

### R04 — 前端 Treemap 渲染性能

| 维度 | 详情 |
|------|------|
| **风险描述** | 数据量过大时 ECharts TreeMap 渲染卡顿或浏览器崩溃 |
| **影响** | 高 — 直接影响核心可视化体验 |
| **概率** | 低 — ECharts 本身性能优秀，且有数据量限制 |
| **影响范围** | 前端可用性 |
| **缓解措施** | 1. API 层控制返回数据量：每层最多 50 个子项，超出合并为"其他"<br>2. 按层级懒加载：点击下钻时才请求下一层数据<br>3. 设置 TreeMap 最大节点数限制（200 个）<br>4. 使用 ECharts 的 `large: true` 大数据优化模式<br>5. 骨架屏 + 渐进渲染，避免白屏等待 |
| **验收标准** | 100 个节点的 TreeMap 渲染 < 500ms，交互流畅无卡顿 |

### R05 — 路径长度限制

| 维度 | 详情 |
|------|------|
| **风险描述** | Windows 传统 API 路径限制 260 字符，深层嵌套目录可能超限 |
| **影响** | 中 — 部分文件无法扫描 |
| **概率** | 低 — 现代 Windows 10/11 已支持长路径 |
| **影响范围** | 扫描完整性 |
| **缓解措施** | 1. 使用 `\\?\` 前缀绕过 260 字符限制（`os.scandir` 支持）<br>2. 捕获 `OSError` 中的路径过长错误，记录到错误表<br>3. 前端提示"跳过了 N 个路径过长的文件" |
| **验收标准** | 路径超过 260 字符的文件被优雅跳过，不影响整体扫描 |

### R06 — 重复文件哈希计算耗时

| 维度 | 详情 |
|------|------|
| **风险描述** | 对大文件计算 MD5 哈希非常耗时，影响整体扫描速度 |
| **影响** | 中 — 拖慢扫描或重复文件检测速度 |
| **概率** | 高 — 用户目录中大文件普遍 |
| **影响范围** | V1.1 重复文件功能的性能 |
| **缓解措施** | 1. **两阶段策略**：先按文件大小分组，只有大小相同的文件才计算哈希<br>2. 最小文件阈值：默认 1MB 以下的文件不计算哈希（减少计算量）<br>3. 延迟计算：哈希不在主扫描流程中计算，用户请求重复文件时才触发<br>4. 分块读取：每次读取 64KB 计算哈希，避免大文件撑爆内存<br>5. 并行计算：多个文件的哈希计算并发执行 |
| **验收标准** | 1000 个候选文件（每个 10MB）的哈希计算 < 30 秒 |

### R07 — 浏览器兼容性

| 维度 | 详情 |
|------|------|
| **风险描述** | 不同浏览器对 ES Modules、WebSocket、CSS 特性的支持差异 |
| **影响** | 低 — 目标用户使用现代浏览器 |
| **概率** | 中 — 可能遇到边缘情况 |
| **影响范围** | 部分用户 |
| **缓解措施** | 1. 目标浏览器：Chrome 90+、Edge 90+、Firefox 90+<br>2. 避免使用过于新的 API（如 `structuredClone`）<br>3. ECharts 和 Tailwind 都有良好的浏览器兼容性<br>4. 测试时覆盖 Chrome 和 Edge |
| **验收标准** | 在 Chrome 和 Edge 上功能完整、样式正确 |

### R08 — WebSocket 连接稳定性

| 维度 | 详情 |
|------|------|
| **风险描述** | WebSocket 连接可能因网络波动或服务重启而断开 |
| **影响** | 低 — 可降级为轮询 |
| **概率** | 中 — 本地服务重启时必然发生 |
| **影响范围** | 实时监控功能 |
| **缓解措施** | 1. 自动重连机制：断开后每 3 秒尝试重连<br>2. 心跳检测：每 30 秒 ping/pong，超时则重连<br>3. 降级策略：WebSocket 不可用时自动切换为 HTTP 轮询（每 5 秒）<br>4. 前端显示连接状态指示器 |
| **验收标准** | 断开后 3 秒内自动重连，降级模式下功能正常 |

## 3. 安全风险

### S01 — 路径遍历攻击

| 维度 | 详情 |
|------|------|
| **风险描述** | API 参数中的路径可能被恶意构造，访问敏感目录 |
| **缓解措施** | 1. 路径参数校验：必须是绝对路径，不允许 `..` 相对路径<br>2. 扫描路径必须是存在的目录<br>3. 服务默认绑定 `127.0.0.1`，不对外暴露<br>4. 排除列表中的路径不可被 API 覆盖 |
| **验收标准** | 恶意路径请求返回 400 错误 |

### S02 — 误删重要文件

| 维度 | 详情 |
|------|------|
| **风险描述** | 清理建议可能误判，导致用户误删重要文件 |
| **缓解措施** | 1. 默认删除到回收站，非物理删除<br>2. 二次确认机制：选中 → 确认清理 → 弹窗确认<br>3. 清理建议附带置信度标识（高/中/低）<br>4. 低置信度建议默认不勾选<br>5. 建议中附带详细理由，帮助用户判断 |
| **验收标准** | 所有删除操作可从回收站恢复 |

### S03 — 服务端口暴露

| 维度 | 详情 |
|------|------|
| **风险描述** | FastAPI 服务如果绑定 0.0.0.0，可能被局域网访问 |
| **缓解措施** | 1. 默认绑定 `127.0.0.1`（仅本机访问）<br>2. 配置文件中明确标注安全风险<br>3. 启动日志中显示绑定地址 |
| **验收标准** | 默认配置下只有本机可访问 |

## 4. 依赖风险

| 依赖 | 风险 | 缓解措施 |
|------|------|---------|
| FastAPI | 版本更新可能引入 breaking changes | 锁定主版本号，定期评估升级 |
| ECharts | CDN 加载失败 | 内置 ECharts 静态文件作为备份 |
| SQLite | 并发写入限制 | 单写多读模式，扫描时独占写入 |
| send2trash | 跨平台行为差异 | 仅支持 Windows，文档说明 |
| Watchdog | Windows 事件延迟 | 设置 debounce 时间，避免重复事件 |
