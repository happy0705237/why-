## 1. 当前决策

### 1.1 产品阶段

第一阶段只面向用户本人自用，目标是做出稳定可演示、可真实扫描本机目录的 MVP。若效果好，再考虑发布给其他用户。

### 1.2 产品参考

体验参考 **SpaceSniffer**：重点突出磁盘空间的块状可视化、快速定位大文件、逐层下钻和直觉式探索。

### 1.3 技术边界

- 后端允许安装 Python 依赖。
- 后端允许调用 Windows 资源管理器，用于“打开文件位置”等本地能力。
- 第一阶段不做真实清理删除、不做重复文件检测、不做实时监控。
- ClaudeCode 执行开发时，采用“目标 + 验收标准”方式下达任务，保留工程实现自主权。

### 1.4 GitHub 仓库

仓库地址：`https://github.com/happy0705237/why-.git`

当前本地仓库尚未提交。首次推送前需要确认 GitHub 认证方式是否已经配置好。

## 2. V1.0 MVP 范围

### 2.1 必须交付

V1.0 的目标是跑通完整核心链路：

```
启动应用 -> 查看磁盘分区 -> 选择目录扫描 -> 查看 TreeMap -> 下钻目录 -> 查看大文件排行 -> 打开文件位置
```

### 2.2 功能范围

| 编号 | 功能 | V1.0 状态 |
|------|------|-----------|
| F01 | 磁盘分区总览 | 必做 |
| F02 | 目录扫描 | 必做 |
| F03 | TreeMap 可视化 | 必做 |
| F04 | 逐层下钻 | 必做 |
| F05 | 大文件排行 | 必做 |
| F06 | 按类型统计 | 必做 |
| F07 | Web 仪表盘 | 必做 |
| F08 | 一键启动 | 必做 |

### 2.3 暂不做

- 清理建议
- 删除到回收站
- 重复文件哈希检测
- 实时监控
- 系统托盘
- 报告导出
- 跨平台支持

这些功能进入 V1.1 或 V1.2。

## 3. 里程碑

### M1：项目可启动

完成标志：

- 有 `requirements.txt`
- 有 `start.py`
- 启动后本地服务监听 `127.0.0.1:8765`
- 浏览器可访问首页

验收方式：

- 运行 `python start.py`
- 打开 `http://127.0.0.1:8765`

### M2：后端核心 API 可用

完成标志：

- `GET /api/disks` 返回本机磁盘分区
- `POST /api/scan` 可以创建扫描任务
- `GET /api/scan/{id}` 可以查询扫描状态
- `GET /api/scan/{id}/tree` 返回目录树
- `GET /api/scan/{id}/files/top` 返回大文件列表
- `GET /api/scan/{id}/files/types` 返回文件类型统计

验收方式：

- 使用浏览器或 curl 调用 API
- 扫描项目目录或用户指定测试目录

### M3：扫描结果可持久化

完成标志：

- 扫描记录写入 SQLite
- 文件和目录信息可查询
- 历史扫描可保留
- 权限不足的文件不会中断扫描

验收方式：

- 扫描一个包含多层目录和不同文件类型的目录
- 重启服务后仍可查看历史扫描

### M4：前端核心体验可用

完成标志：

- 首页展示磁盘卡片
- 可输入或选择扫描路径
- 扫描中有进度反馈
- 扫描完成后显示 TreeMap
- 点击目录块可下钻
- 面包屑可返回上级
- 大文件排行和类型统计可查看

验收方式：

- 完成一次端到端手动测试

### M5：本地体验打磨

完成标志：

- 可打开文件所在位置
- 错误提示清晰
- 空状态、加载状态、扫描失败状态完整
- README 与实际启动方式一致

验收方式：

- 用户按 README 操作即可运行

## 4. 质量要求

### 4.1 性能底线

- 扫描 10 万文件目标小于 10 秒；若达不到，需说明瓶颈并保证界面不卡死。
- TreeMap 每层最多展示 Top 50 项，其余合并为“其他”。
- 后端扫描应分批处理，避免一次性把所有文件放入内存。

### 4.2 安全底线

- V1.0 不实现删除能力。
- 后端默认只绑定 `127.0.0.1`。
- 路径必须是本机存在的绝对路径。
- 权限不足、路径过长、文件被占用时记录错误并跳过。

### 4.3 体验底线

- 暗色仪表盘风格。
- TreeMap 是首要视觉区域。
- 数据密度高于装饰性。
- 不做营销首页，打开即进入工具界面。
