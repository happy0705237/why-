### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **分层清晰** | 路由层 → 服务层 → 核心引擎 → 数据层，职责单一 |
| **扫描与展示分离** | 扫描是异步任务，通过轮询/推送获取结果 |
| **只读优先** | 默认只读扫描，清理操作需要显式确认 |
| **容错优先** | 文件权限不足、路径过长等情况优雅降级，不中断整体流程 |
| **渐进加载** | 大目录扫描采用流式输出，前端增量渲染 |

### 3.2 核心模块详细设计

#### scanner.py — 扫描引擎

```
职责：递归遍历目录，收集文件/目录的大小和元信息

核心方法：
- scan_directory(path, options) → AsyncGenerator
  - 使用 os.scandir() 高性能遍历
  - 异步生成器，每扫描一批就 yield 结果
  - 支持并发扫描多个子目录（asyncio + ThreadPoolExecutor）
  - 权限不足时记录错误但不中断

性能优化：
- os.scandir() 比 os.listdir() + os.path.getsize() 快 5-10 倍
- 使用 ThreadPoolExecutor 并发扫描子目录
- 大目录分批写入数据库，避免内存爆炸
- 支持 max_depth 参数控制扫描深度
```

#### analyzer.py — 分析引擎

```
职责：基于扫描结果生成清理建议

建议规则（V1.1）：
- 临时文件：%TEMP%, Windows\Temp, 浏览器缓存目录
- 日志文件：*.log, *.log.old, 日志目录
- 重复文件：大小相同的文件 → MD5 哈希确认
- 长期未访问：last_access > N天 且 size > 阈值
- 安装包残留：*.msi, *.exe (在 Downloads 中超过30天)

每条建议包含：
- type: 临时文件 / 缓存 / 日志 / 重复 / 长期未访问 / 安装包
- target_path: 文件路径
- size: 文件大小
- reason: 人类可读的推荐理由
- confidence: 高 / 中 / 低
```

#### database.py — 数据存储层

```
职责：SQLite 异步操作封装

设计要点：
- 使用 aiosqlite 异步操作
- 表结构详见 DATABASE.md
- 批量插入使用 executemany + 事务
- 索引优化：scan_id, path, size, modified_at
- 支持数据库迁移（版本号跟踪）
```

## 4. 数据流设计

### 4.1 扫描流

```
用户选择目录
    │
    ▼
POST /api/scan  ─→  创建 Scan 记录（status=pending）
    │
    ▼
异步启动扫描任务
    │
    ├──→ scanner.scan_directory()
    │       │
    │       ├──→ os.scandir() 递归遍历
    │       │
    │       ├──→ 批量写入 files 表
    │       │
    │       ├──→ 累加 directories 表
    │       │
    │       └──→ WebSocket 推送进度
    │
    ▼
扫描完成（status=completed）
    │
    ▼
前端轮询 /api/scan/{id} 获取结果
    │
    ▼
渲染 TreeMap + 统计图表
```

### 4.2 清理流

```
GET /api/scan/{id}/suggestions
    │
    ▼
analyzer 分析扫描结果
    │
    ├──→ 规则 1：临时文件路径匹配
    ├──→ 规则 2：文件大小 + 时间筛选
    ├──→ 规则 3：哈希比对找重复
    │
    ▼
返回建议列表
    │
    ▼
用户勾选建议项
    │
    ▼
POST /api/cleanup/execute  ─→  二次确认
    │
    ▼
send2trash 移动到回收站
    │
    ▼
更新扫描记录中的释放空间
```

### 4.3 实时监控流（V1.2）

```
Watchdog 监听目录
    │
    ├──→ on_created()  ─→  通知 WebSocket
    ├──→ on_modified() ─→  通知 WebSocket
    ├──→ on_deleted()  ─→  通知 WebSocket
    │
    ▼
WebSocket 推送到前端
    │
    ▼
前端实时更新事件流 + 趋势图
```

## 5. 并发模型

```
┌─────────────────────────────────────────────┐
│              uvicorn (ASGI Server)           │
│                                             │
│  ┌─────────────┐    ┌────────────────────┐  │
│  │  主事件循环  │    │  扫描线程池        │  │
│  │  (asyncio)   │    │  ThreadPoolExecutor│  │
│  │              │    │  (max_workers=4)   │  │
│  │  - API 请求  │───→│  - 文件系统 I/O    │  │
│  │  - WebSocket │    │  - 哈希计算        │  │
│  │  - 数据库操作│    │                    │  │
│  └─────────────┘    └────────────────────┘  │
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │  后台任务                           │    │
│  │  - 扫描任务（asyncio.Task）         │    │
│  │  - 监控任务（Watchdog 线程）        │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

说明：
- FastAPI 的请求处理运行在 asyncio 事件循环中
- 文件系统扫描是阻塞 I/O，放到 ThreadPoolExecutor 中执行
- 扫描任务通过 asyncio.create_task() 异步执行，不阻塞 API 响应
- 进度通过 WebSocket 推送，前端实时更新

## 6. 错误处理策略

| 错误类型 | 处理方式 | 用户感知 |
|---------|---------|---------|
| 文件权限不足 | 跳过该文件，记录到扫描日志 | 扫描完成后提示"跳过了 N 个无权限文件" |
| 路径过长 (>260字符) | 跳过，记录日志 | 同上 |
| 文件被占用（删除时） | 提示文件正在使用 | 弹窗提示"该文件正在被使用，无法删除" |
| 磁盘空间不足 | 扫描正常执行（只读） | 无影响 |
| 数据库写入失败 | 重试 3 次后放弃该批次 | 扫描结果可能不完整，提示用户 |
| 网络中断（WebSocket） | 自动重连 + 轮询降级 | 前端短暂断开后自动恢复 |
| 扫描超大目录 | 分批处理 + 进度条 | 显示扫描进度和已扫描文件数 |

## 7. 安全设计

| 维度 | 措施 |
|------|------|
| **本地访问** | 服务默认绑定 127.0.0.1，不对外暴露 |
| **删除安全** | 使用 send2trash 删除到回收站，非物理删除 |
| **路径校验** | API 参数校验，防止路径遍历攻击 |
| **权限控制** | 只读扫描不需要管理员权限，清理操作提示 UAC |
| **敏感目录** | 默认排除系统关键目录（System32, Program Files 等） |

## 8. 扩展性设计

| 扩展点 | 设计方式 |
|--------|---------|
| 清理规则 | 规则引擎模式，新增规则只需实现 AnalyzerRule 接口 |
| 存储后端 | 通过抽象层隔离 SQLite，可替换为 PostgreSQL 等 |
| 前端图表 | 组件化设计，新增图表类型不影响现有代码 |
| 文件监控 | Watchdog 封装为独立模块，可替换监控策略 |
| 导出格式 | 导出服务接口化，可扩展 PDF、CSV 等格式 |
